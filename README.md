# IdentityAndFaciltityCore

دو سرویس پنل امید بانک، کنار هم:

| پوشه | چیست |
|---|---|
| `identityservice/` | سرویس هویت و مجوز پنل — ورود، نشست، نقش‌ها و دسترسی‌ها. مبنا: نسخهٔ خام ۱۷ مهر ۱۴۰۵، به‌علاوهٔ مدل «دسترسی به نقش، نقش به کاربر، با دامنه». |
| `facilityservice/` | سرویس تسهیلات — شرکت‌ها، پرسنل، تخصیص وام، تأییدها، داشبورد و گزارش تغییرات. |
| `identity-changes/` | فقط برای مرور: فایل‌های تازه و عوض‌شدهٔ Identity نسبت به نسخهٔ خام، به‌علاوهٔ دیف کامل. کد قابل build در `identityservice/` است. |

## مجوز، در یک نگاه

مجوز به **نقش** داده می‌شود و نقش به **کاربر**، و دامنه روی **انتساب نقش** می‌نشیند — پس یک
نفر می‌تواند یک نقش را در دو شعبه داشته باشد:

```
PanelUser → PanelUserRole → Role → RolePanelMenu → PanelMenu
            (دامنه این‌جا)                  (کلید مجوز این‌جا)
```

Facility مجوز را خودش نمی‌داند؛ توکن را به Identity می‌دهد و مجوزهای مؤثر را می‌گیرد.
هر مسیری که کلید اعلام نکند **بسته** است و لاگ می‌شود.

## سند

- `identityservice/docs/Panel-Access-API.md` — ۲۰ مسیر پنل دسترسی، با ورودی/خروجی و جدول خطا
- `facilityservice/docs/Facility-Frontend-Answers.md` — پاسخ مورد‌به‌مورد به مغایرت‌های API که فرانت گزارش کرده بود
- `facilityservice/docs/Facility-Flows.md` و `Facility-ER.md` — جریان‌ها و مدل داده
- `identity-changes/README.md` — فهرست تغییرات Identity با دلیل هر کدام

## وضعیت build

هیچ‌کدام از دو سرویس در این محیط build نشده‌اند (SDK نصب نبود). امضاها دستی بررسی شده‌اند،
ولی اولین `dotnet build` را خودتان بزنید. دو فرض Identity که باید تأیید شود در
`identity-changes/README.md` نوشته شده است.
